## Confirmed decisions and edge policies

- Grade subscores independently after crash, collision or escape. Use FlightResult.did_reach_orbit for 20 safe-final-orbit points; only LAUNCH_FAILURE activates the zero-score override.
- Open/missing final elements earn zero altitude/shape accuracy and coverage. Scoring consumes the reported coverage; it does not recompute Kepler mathematics.
- Zero installed instruments earns all 5 health points. Otherwise health is the working/installed ratio, clamped to 0-1.
- Instrument fit measures the best science instrument carried, rather than summing ratings or removing fit points when an instrument fails; health and delivered data reflect failures.
- Preserve unrounded totals, including negative values and values above 100. Existing exact band thresholds are unchanged.
- Zero tolerance requires an exact match. A selected science objective with a zero requirement earns full points for that requirement; an absent objective earns zero science points.
- For a zero or negative budget, zero cost earns 25 budget points and positive cost earns -25; no saving margin is awarded. Unknown quest conditions fail and reclaim their grant. The defined failure penalty is capped at 30 beyond three failures; shipped missions currently offer one quest each.
- No power/lifetime model, new event-rate tuning, replay feature, planning-screen or execution-screen implementation was added.

## New helpers and demo

- MissionPresentation provides create_theme, add_background, add_label, add_monitor, clear_contents and zone_text for T04 presentation only; other tasks need not depend on it.
- GeneratePortraits.gd is an idempotent generator preserving existing images. Run Godot headless with --script res://scripts/mission/GeneratePortraits.gd, then import.
- Open res://scenes/development/T04_demo.tscn in Godot and run the scene. The footer selector switches among normal, fractional, failed-grant, launch-failure, long-log, orbit-lost and unscored reports. The failed-grant scenario uses synthetic development-only quests.
- Score breakdown and Flight event log buttons switch the scrollable panel. Inspect both the beginning and end of long content. Back to main menu exercises the normal production navigation.
- For repeatable rendered captures, run the demo with -- --capture-directory=<absolute-output-directory>; this renders all result scenarios and both mission briefings, saves PNG files, then exits. Use a graphical renderer, not --headless. Capture files belong in .godot or another temporary directory.
