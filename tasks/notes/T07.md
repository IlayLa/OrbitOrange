# T07 hand-back

## Flight behavior

- The director reads mission hazards and accepted side quests once per flight. It rolls in event ID order on five-second flight ticks. Both mission catalogues contain the same initial rates, marked as placeholder gameplay values. No observed collision, debris or solar-weather data informs these rates.
- Per the gameplay clarification, each normal launch randomizes its event generator independently of the rocket design and player actions. Explicit seeds remain available to the isolated test and demo flights. This replaces the production seed rule in the original T07 specification.
- Satellite and asteroid collisions are fatal. Debris fragments can disable working instruments. Radar reveals a threat through the existing T03 contract. A flight without working radar can get a late warning. T03's proximity lamp remains independent.
- The overlay previews a candidate coast with the existing rocket and orbit models. Executing uses the live flight's burn outcome. Ignoring an encounter leaves the current path and propellant in place.
- The final screen reads the existing event log. Avoidance awards no direct points.
- Collision checks inspect the actual paths flown between ticks, even around a burn. Collision consequences are delivered on the next fixed tick, so a scheduled burn later in that interval can already have fired. T03's physical end reason retains priority on its terminal tick.

## Demo and test entry points

- An isolated director can bind to a test or demo flight with `configure`, inject a catalogue event with `force_event`, register a placed encounter with `force_encounter`, or accept Execute or Ignore through `acknowledge_alert`. The production director binds to the existing flight autoload.

## Contract requests

1. **T03 telemetry interference.** Add `FlightSimulation.set_telemetry_interference(noise_fraction_addition: float, dropout_probability_addition: float) -> void`. T03 should apply the additions at its next normal instrument sample using its existing RNG and clamp the resulting dropout probability. Zero additions clear the effect. Reset the T03-side values on flight start. T07 owns the 120-second simulated timer and scales the additions by 1.0 without a working computer, 0.5 with a basic computer, or 0.25 with a hardened computer. Without this hook a flare is tracked and logged, and the flight's instrument readings retain their usual behavior.
2. **T03 flight forecast after a vehicle fault.** Add `FlightSimulation.refresh_flight_forecast() -> void`. Recompute the delivery and resulting trajectory of pending burns against the live vehicle while preserving the next burn's already scheduled time and revolution progress. The player's emergency pulse still restarts the remaining revolution count per T09. The live engine uses its damaged state when it fires today. Until the refresh hook is supplied, predictions for future burns can still reflect the earlier vehicle state.

T07 can call the hooks when present. The integrator owns routing these requests to T03. No T03-owned files were changed in T07.
